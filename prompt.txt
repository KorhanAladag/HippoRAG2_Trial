VERIFIED FACTS ABOUT HippoRAG 2.0.0a4

I read these from the installed package, so treat them as given rather than
guessing:

1. QuerySolution is a dataclass in hipporag/utils/misc_utils.py with fields:
   question: str
   docs: List[str]
   doc_scores: np.ndarray
   answer: str
   gold_answers: List[str]
   gold_docs: Optional[List[str]]

2. retrieve(queries, num_to_retrieve) returns List[QuerySolution] when
   gold_docs is not passed. rag_qa(queries) returns a 3-tuple whose first
   element is List[QuerySolution].

3. docs contains passage TEXT, not hash ids. In HippoRAG.py the line is:
   top_k_docs = [self.chunk_embedding_store.get_row(self.passage_node_keys[idx])["content"]
                 for idx in sorted_doc_ids[:num_to_retrieve]]
   So the hash is used internally and then discarded.

4. Passage hash ids are computed as:
   prefix + md5(content.encode()).hexdigest()
   where prefix is "chunk-" for passages and "entity-" for phrases. No
   stripping, lowercasing or other normalisation is applied to the content
   before hashing.

5. hipporag.chunk_embedding_store exposes a text_to_hash_id dict mapping the
   exact stored text to its hash id. This is a more reliable way to recover
   the id than rehashing, because it cannot drift if the hashing changes.

MY SETUP

- Chunks come from MariaDB, not a docs folder. Each row has filename,
  chunk_id, content, plus metadata, start_index, end_index.
- index.py calls prepare_docs, which drops empties, deduplicates, and merges
  short chunks within document boundaries. It writes passage_map.json mapping
  each HippoRAG passage hash to the source chunks that produced it. I fetch
  filename per chunk, so the map can carry filename as well as chunk_id.
- hippo_factory.py builds the HippoRAG object from settings.py, which reads
  .env via python-dotenv.
- query.py has two modes: default rag_qa, and --retrieve which shows passages
  only. It prints answers and reports median and p95 latency.

6. rag_qa() calls retrieve() without num_to_retrieve, so it defaults to
   retrieval_top_k (200 in my config). The truncation to qa_top_k happens
   later, inside qa(), at the line:
   retrieved_passages = query_solution.docs[:self.global_config.qa_top_k]
